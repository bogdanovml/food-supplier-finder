# Food Supplier Finder

> Аналитический B2B-сервис глубокого поиска, юридической проверки, скоринга и сравнения оптовых поставщиков продуктов питания, сырья, ингредиентов и упаковки с модулем рассылки запросов КП (RFQ).

* **Работающий сервис (демо):** [https://maxim.org.ru/supplier-finder/](https://maxim.org.ru/supplier-finder/)
* **Стек:** Python 3.12 / FastAPI (SSE) / SQLite / Playwright / Vanilla JS + Tabulator.js + Bootstrap 5 / Nginx / systemd

---

## 1. Назначение и решаемая задача

Поиск надёжных поставщиков в сфере Food / HoReCa вручную отнимает у отдела закупок часы и дни:
* Обычные поисковики выдают дорвеи, кулинарные блоги с рецептами, розничные магазины и агрегаторы;
* Телефонные справочники содержат устаревшие или ликвидированные 10 лет назад организации;
* Поставщики из смежных сфер (зарыбление прудов, малёк, семена для дачников, рыболовные снасти) засоряют выдачу;
* Карточки без реквизитов и цен заставляют тратить время на пустые звонки.

**Food Supplier Finder** автоматизирует полный цикл работы закупщика: от параллельного сбора из независимых каналов и отсева мусора до проверки финансовой отчётности в ФНС и отправки персональных запросов КП с контролем ответов.

## 2. Архитектура сквозного конвейера

Поиск работает как прозрачный конвейер в реальном времени через Server-Sent Events (SSE). Закупщик наблюдает за прогрессом каждого шага:

```
[01. План]       LLM генерирует B2B-запросы (местные + федеральные) + коды ОКПД2 и ОКВЭД2
     │
[02-05. Сбор]    Параллельный опрос 4 каналов:
     │           ├── Яндекс Live + Google XML (XMLStock, топ-20 по региону закупки)
     │           ├── B2B-каталог оптовиков optlist.ru (Playwright)
     │           ├── Реестр исполненных контрактов 44-ФЗ (Госплан API + стемминг)
     │           └── Отраслевой каталог юрлиц orgpage.ru
     │
[06. Merge]      Слияние дубликатов по домену и ИНН + ранняя LLM-вычитка розницы и агрегаторов
     │
[07. Проверка]   Юридический и финансовый аудит:
     │           ├── ЕГРЮЛ через DaData (статус, реквизиты, руководитель)
     │           ├── Официальная финотчётность ФНС БФО (bo.nalog.gov.ru: выручка, прибыль, активы)
     │           └── Контакты и сайты из Checko (через ротацию российских HTTP/2 прокси)
     │
[08. Обход]      Глубокое обогащение сайтов:
     │           ├── Быстрый парсинг SSR гидратации и Schema.org (0.1 мс, bypass браузера)
     │           ├── Headless Chromium (Playwright) для сложных SPA-оболочек
     │           └── Параллельный сбор страниц «О компании», «Доставка», «Контакты»
     │
[09. Скоринг]    Двухуровневая фильтрация качества:
     │           ├── Строгий фильтр пищевой релевантности (anti-offtopic)
     │           ├── Географический фильтр («Присутствует ИЛИ подтверждённо доставляет»)
     │           └── Проверка народной репутации на Яндекс Картах
     │
[10. Готовность] Рабочее место закупщика: досье, скоринг, сравнение, экспорт в XLSX, RFQ
```

## 3. Ключевые инженерные решения

### 3.1. Юрлицо и аудит первоисточников (Data Provenance)
В B2B карточка без проверенного юрлица бесполезна. 
* Статус организации, выручка, чистая прибыль/убыток (стр. 2400) и балансовые активы (стр. 1600) запрашиваются напрямую из официального ресурса **БФО ФНС России (`bo.nalog.gov.ru`)** без платных шлюзов.
* Любой факт в карточке (телефон, цена, условия доставки, сертификаты) имеет проверяемую ссылку на источник (страница сайта, номер контракта Госплана, запись реестра ФНС).
* Карточки, не прошедшие проверку качества (анонимы, ликвидированные фирмы, чужие города, слепые заглушки), изолируются на отдельной вкладке **«Отсеянные»** с цветным бейджем причины (`no_legal`, `inactive`, `geo`, `not_supplier`, `offtopic`, `no_substance`).

### 3.2. Парсинг SSR-гидратации и оптимизация скорости (ускорение в 2.5 раза)
Вместо тяжёлого запуска Playwright на каждый сайт внедрён легковесный анализатор встроенных данных `extract_embedded_payload`:
* За **0.08 мс** извлекает структурированный JSON из разметки **Schema.org JSON-LD** (`Organization`, `LocalBusiness`, `Store`, `Product`), а также стейтов **Next.js (`__NEXT_DATA__`)**, **Nuxt**, **Inertia.js (`data-page`)**, **Redux SSR**, **Remix** и **Apollo GraphQL**.
* Если контакты и товарный профиль найдены в гидратации — запуск Chromium отменяется, экономя по 4–5 секунд и сотни мегабайт RAM на сайт.
* Полный цикл конвейера сокращён с 298 с до **~118–170 с**.

### 3.3. Строгая фильтрация непищевых товаров и гео-привязки
* **Anti-offtopic**: система распознаёт и отсекает товары и услуги непродовольственного назначения (живой малёк для зарыбления прудов, аквариумистика, рыболовные снасти, семена для дачников, корма для животных).
* **Присутствует ИЛИ доставляет**: карточка считается региональной, если склад/офис находится в целевом регионе либо подтверждена доставка в данный субъект / по всей РФ. Локальные магазины с доставкой «только по Москве в пределах МКАД» исключаются из региональных поисков.

### 3.4. Ротация прокси с поддержкой HTTP/2
* Модуль `app/proxy.py` обеспечивает round-robin ротацию пула российских прокси с автоматическим кулдауном при HTTP 429 и поддержкой протокола HTTP/2 (`h2` + `httpx[http2]`), что исключает блокировки и капчи при запросах к реестрам.

## 4. Почтовый контур RFQ (Запрос коммерческих предложений)

Модуль `app/rfq.py` предоставляет закупщику готовый инструмент проведения закрытого тендера:

1. **Индивидуальная рассылка (no-shared-copies)**:
   * Каждому контрагенту формируется и отправляется **отдельное персональное письмо** через защищённое соединение SSL (порт 465).
   * Поставщики не видят чужих адресов и не знают о конкурентах в рассылке.
2. **Суточный лимит безопасности**:
   * Встроенный rate-limiter ограничивает рассылку **50 письмами в сутки** для защиты репутации домена от спам-фильтров.
3. **Безопасный тестовый режим (по умолчанию)**:
   * Включается по умолчанию в модальном окне: запросы направляются на 3 тестовых ящика (`supplier1..3@maxim.org.ru`).
   * **Робот-автоответчик**: тестовые ящики вычитывают входящие запросы через IMAP и отправляют автоматическое деловое подтверждение о принятии запроса в работу.
4. **Боевой режим и ручной ввод**:
   * Переключатель в «Боевой режим» направляет письма реальным поставщикам из найденной выборки.
   * Доступно поле ручного добавления произвольных email-адресов.
   * Переключение режимов происходит мгновенно без сброса отредактированного закупщиком текста письма.
5. **Встроенный раздел «Ответы поставщиков» (IMAP)**:
   * В шапке сайта выводится кнопка с бейджем непрочитанных писем.
   * Встроенный почтовый клиент позволяет просматривать входящие коммерческие предложения от контрагентов прямо в интерфейсе без перехода в сторонние почтовые программы.

## 5. Стек технологий

| Компонент | Технологии | Назначение |
|---|---|---|
| **Backend** | Python 3.12, FastAPI, Uvicorn, asyncio | Асинхронное ядро API, SSE-стриминг событий |
| **База данных** | SQLite (WAL-ready) | Zero-ops хранилище поисков, поставщиков, кэша ФНС и Checko |
| **Сбор данных** | `httpx` (HTTP/2), Playwright Chromium, XMLStock | Параллельный опрос поисковиков, каталогов и сайтов |
| **Извлечение** | `trafilatura`, `price-parser`, `tldextract`, `rapidfuzz` | Очистка DOM, нормализация цен, доменный дедуп |
| **Нейросети** | OpenAI-compatible endpoint | Вычитка нерелевантных сайтов, фактоидный анализ, RFQ-письма |
| **Почтовый шлюз** | `aiosmtplib`, `imaplib`, SSL 465 / 993 (Beget) | Персональная SMTP-отправка и чтение входящих по IMAP |
| **Frontend** | Vanilla JS, Bootstrap 5, Tabulator.js | Строгий Enterprise B2B-интерфейс без эмодзи и без сборщиков |
| **Экспорт** | `xlsxwriter` | Выгрузка выборки в Excel с автофильтрами и стилями |

## 6. Локальный запуск и развёртывание

### 6.1. Быстрый запуск (one-liner)
```bash
git clone <repo-url>
cd supplier-search
./run.sh
```
Скрипт `./run.sh` автоматически создаст `.venv`, установит зависимости, загрузит Chromium для Playwright и запустит сервис на порту `8000`.

### 6.2. Ручная установка
```bash
# 1. Создание виртуального окружения
python3 -m venv .venv
source .venv/bin/activate

# 2. Установка зависимостей и браузера
pip install "fastapi>=0.115" "uvicorn[standard]>=0.32" "httpx[http2]>=0.28" "h2>=4.1.0" \
  "pydantic-settings>=2.6" "sse-starlette>=2.1" "jinja2>=3.1" "trafilatura>=1.12" \
  "price-parser>=0.4" "rapidfuzz>=3.0" "tldextract>=5.1" "playwright>=1.40" \
  "xlsxwriter>=3.2" "aiosmtplib>=3.0" "email-validator>=2.2"
playwright install chromium

# 3. Настройка окружения
cp .env.example .env
# Заполните ключи в .env

# 4. Запуск веб-сервера
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Сервис будет доступен по адресу: `http://127.0.0.1:8000`

## 7. Конфигурация (.env)

Все секреты, токены и пароли хранятся исключительно в файле `.env`, который добавлен в `.gitignore` и никогда не попадает в репозиторий.

Для развёртывания скопируйте `.env.example` в `.env` и укажите параметры:
* `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL_SIMPLE`, `LLM_MODEL_SMART` — доступ к нейросетевому эндпоинту;
* `XMLSTOCK_USER`, `XMLSTOCK_KEY`, `XMLSTOCK_*_URL` — доступ к Яндекс и Google XML;
* `DADATA_API_KEY`, `DADATA_SECRET` — валидация контрагентов в ЕГРЮЛ;
* `SMTP_*`, `IMAP_*` — реквизиты почтового ящика для отправки и приёма RFQ;
* `TEST_SUPPLIER_*_PASS` — пароли тестовых ящиков поставщиков.
