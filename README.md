# Food Supplier Finder

> Аналитический сервис поиска, скоринга и сравнения поставщиков продуктов питания, сырья, ингредиентов и пищевой упаковки.

Прототип разработан в рамках тестового задания (`docs/task.md`). Сервис объединяет региональный веб-поиск (Яндекс и Google XML), отраслевые базы (каталог `optlist.ru`) и реестр исполненных контрактов `44-ФЗ` (Госплан API), обогащает карточки поставщиков на лету и предоставляет рабочее место закупщика для принятия решения.

---

## 1. Концепция и ключевая идея

Классический справочник поставщиков быстро устаревает и скрывает происхождение данных. **Food Supplier Finder** работает как прозрачный конвейер поиска и аналитики в реальном времени:

1. **Многоканальный сбор**: одновременный опрос 3 независимых источников с поддержкой graceful degradation (отказ одного источника не прерывает поиск).
2. **Прозрачность конвейера (SSE)**: пользователь наблюдает 8 этапов обработки в реальном времени, видит поисковые запросы, тайминги и найденные объемы.
3. **Обогащение и дедупликация**: слияние карточек по ИНН, доменам (`tldextract`) и нечетким наименованиям (`rapidfuzz`). Автоматический обход сайтов: извлечение контактов, цен (`price-parser`), сертификатов (ХАССП, ГОСТ) и минимального заказа (MOQ) с очисткой через `trafilatura`.
4. **Аудит первоисточников (Data Provenance)**: каждый факт в карточке поставщика снабжен проверяемой ссылкой на источник (номер госконтракта, ссылка на каталог или конкретная страница сайта).
5. **Инструменты принятия решений**:
   - Матрица прямого сравнения параметров (side-by-side comparison matrix)
   - Воронка статусов работы с поставщиком (`Новый` → `КП запрошено` → `В переговорах` → `Контракт`)
   - Внутренние заметки закупщика с хронологией
   - Конструктор RFQ (запрос коммерческого предложения) с генерацией через LLM и возможностью ручной редакции
   - Экспорт выборки в форматированный Excel (XLSX с автофильтрами) и CSV для Google Таблиц

## 2. Архитектура и стек технологий

Подробное обоснование архитектурных решений приведено в [docs/architecture.md](docs/architecture.md) и [docs/oss-choices.md](docs/oss-choices.md).

| Слой | Технология | Обоснование |
|---|---|---|
| **Backend** | Python 3.12+ / FastAPI / Uvicorn | Асинхронность из коробки для параллельного опроса источников; нативный SSE-транспорт (`sse-starlette`) |
| **База данных** | SQLite (чистый SQL, WAL-ready) | Zero-ops: локальный файл без подъема инфраструктуры, легко мигрируется в PostgreSQL |
| **Источники данных** | XMLstock (Яндекс + Google XML), `optlist.ru` (Playwright), Госплан API (44-ФЗ) | Комплексное покрытие: органика + отраслевой каталог + фактические цены закрытых госконтрактов |
| **Извлечение данных** | `trafilatura`, `price-parser`, `rapidfuzz`, `tldextract` | Индустриальные open-source библиотеки вместо хрупких самописных регулярок |
| **Нейросетевой слой** | OpenAI-compatible endpoint (двухуровневая маршрутизация) | Легкая модель (`gemma4:31b`) — планирование запросов; глубокая (`gemini-3.8-flash-high`) — аналитические выжимки и RFQ |
| **Frontend** | Vanilla JS + Bootstrap 5 + Tabulator.js | Легковесный B2B-интерфейс без сборщиков (Webpack/Vite) — запуск одной командой `run.sh` |
| **Экспорт и RFQ** | `xlsxwriter`, `aiosmtplib`, `email-validator` | Профессиональное форматирование Excel; неблокирующая отправка почты |

## 3. Источники данных

1. **Региональная выдача Яндекс XML (`lr=`) и Google XML**:
   - Находит официальные сайты производств и оптовиков в целевом регионе.
   - Запросы строятся автоматически с помощью LLM-планировщика на первом этапе.
2. **Оптовый каталог `optlist.ru`**:
   - Профильный B2B-каталог производителей продуктов питания.
   - Сбор выполняется через браузерную автоматизацию Playwright с обходом защиты Anubis PoW.
   - Извлекает минимальный объем заказа (MOQ), способы доставки, верификацию документов и контакты.
3. **Реестр исполненных контрактов 44-ФЗ (Госплан API)**:
   - Поставщики, имеющие подтвержденный опыт поставок продукции госзаказчикам.
   - **Фактические цены исполнения контрактов** (реальные деньги, а не витринный прайс-лист).
   - Верифицированные ИНН, КПП и юридические адреса.

## 4. Быстрый запуск

### Требования
- Python 3.11+
- Доступ в интернет для внешних API

### Запуск через скрипт (рекомендуется)
```bash
git clone <repo-url>
cd supplier-search
./run.sh
```
Скрипт автоматически создаст `.venv`, установит зависимости, скачает браузер Chromium для Playwright и запустит веб-сервер.

### Ручной запуск
```bash
# 1. Виртуальное окружение
python3 -m venv .venv
source .venv/bin/activate

# 2. Зависимости
pip install -r requirements.txt
playwright install chromium

# 3. Конфигурация (.env в .gitignore, секреты не попадают в репозиторий)
cp .env.example .env
# Отредактируйте .env при необходимости

# 4. Запуск сервера
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Приложение доступно по адресу: **http://127.0.0.1:8000**

## 5. Демонстрационный сценарий для проверки

1. **Поиск**:
   - Введите запрос `мука пшеничная в/с`, выберите регион `Москва` и нажмите «Найти поставщиков».
   - Наблюдайте за карточками этапов в реальном времени: генерация запросов → параллельный сбор → слияние → обход сайтов → скоринг.
2. **Фильтрация и аналитика**:
   - Изучите KPI-сводку (общее число, поставщики с контактами, с подтвержденными ценами).
   - Переключитесь на вкладку `44-ФЗ Контракты` для просмотра поставщиков с реальным опытом и суммами контрактов.
3. **Досье контрагента**:
   - Кликните на кнопку «Досье» в любой строке.
   - Обратите внимание на блок **«Аудит источников данных (Provenance)»** — видно, откуда получен каждый факт.
   - Измените статус поставщика (например, на `В переговорах`) и добавьте внутреннюю заметку закупщика.
4. **Сравнительный анализ**:
   - Отметьте чекбоксами 2–3 поставщика.
   - Нажмите кнопку **«Сравнить выбранных»**.
   - Оцените матрицу параметров: цены, MOQ, стандарты ХАССП/ГОСТ, опыт и контакты.
5. **Запрос КП (RFQ)**:
   - В окне сравнения или тулбаре нажмите «Запросить КП (RFQ)».
   - Проверьте сформированный текст письма. Отредактируйте его при необходимости.
   - Нажмите «Открыть в почтовой программе» (генерация `mailto:`) либо отправьте через SMTP при наличии настроек в `.env`.
6. **Выгрузка**:
   - Нажмите «Экспорт XLSX» для получения готовой таблицы с автофильтром и гиперссылками.

## 6. Безопасность

- Все API-ключи, эндпоинты провайдеров и SMTP-пароли хранятся исключительно в файле `.env`.
- Файл `.env` включен в `.gitignore` и никогда не попадает в систему контроля версий.
- В коде реализована fail-fast валидация: сервис не запустится без корректного окружения и выведет список недостающих параметров.
