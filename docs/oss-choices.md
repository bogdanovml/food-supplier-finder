# Выбор технологий: готовый опенсорс vs собственный код

Критерий: прототип тестового задания — берём готовое там, где оно даёт
качество/надёжность без роста сложности, и пишем своё только там, где
готового нет. Ниже — разбор по блокам (актуально для обоснования решения).

## Что переиспользовано из существующих проектов (прошлые наработки)

| Блок | Откуда взято | Что именно |
|---|---|---|
| SERP-клиент | `AI/seo/clustering` (XMLstockClient) | парсер `<yandexsearch>` XML, региональный `lr`, семафоры — адаптирован, допилен Google |
| Госплан-клиент | `tender/nmck` (GosplanClient) | знания про таймауты/retries/read-разрывы API, схема деталей контракта |
| Price extraction | `ai-tools.su/search` (price_extractor) | идея «дешёвый regex → дорогой LLM fallback», структура PriceResult |
| LLM-клиент | `tender/nmck` (llm.py) | retry-логика, OpenAI-compatible payload |
| Формат RFQ-письма | `web/text-gen` (drafter) | структура письма: контекст → требование → вопрос |

## Готовый опенсорс: принято к использованию

| Блок | Библиотека | Почему | Что заменяет |
|---|---|---|---|
| Извлечение основного текста страницы | **trafilatura** (GPL, индустриальный стандарт, топ benchmark-ов) | вычищает навигацию/рекламу/JS-мусор; на выходе чистый текст → LLM получает сигнальный текст, а не простыню; меньше токенов = дешевле и точнее | самописный `_text_of` (для LLM-слоя; regex-контакты всё равно по полному тексту — телефоны живут в футере) |
| Парсинг цен | **price-parser** (Zyte, Apache-2.0) | `Price.fromstring("от 850 руб./кг") -> 850, руб.` — проверено на русских форматах; даёт Decimal для сортировки/сравнения | самописные regex-нормализации цен при сборке price_min/max |
| Нечёткая дедупликация компаний | **rapidfuzz** (MIT) | token_sort/partial ratio: «ООО «РисОптТорг»» vs «РисОптТорг» = 100, разные мельницы = 46 — устойчивое слияние карточек из 3 источников | наивное сравнение строк |
| Экспорт XLSX | **openpyxl** | стандарт де-факто | — |
| Браузерный обход | **Playwright** (Apache-2.0) | единственный способ сквозь Anubis PoW на optlist | — |
| Веб/бэкенд | **FastAPI + Uvicorn** | SSE, async, автодока OpenAPI | — |
| БД | **SQLite** (stdlib) | один файл, нулевой ops | — |

## Готовый опенсорс: рассмотрено и отклонено (осознанно)

| Решение | Почему нет (для прототипа) |
|---|---|
| **crawl4ai / firecrawl** (LLM-friendly краулеры) | Тяжёлые: тянут свой playwright-стек, конфигурацию, storage. Наша задача — 1 fetch + extraction на ~12 URL за поиск; ~60 строк httpx-кода закрывают это без зависимости. В prod — кандидат №1 при росте объёмов обхода |
| **Scrapy** | фреймворк под crawls-пайплайны тысяч страниц; у нас точечный параллельный fetch |
| **instructor / litellm / pydantic-ai** (structured LLM output) | наши LLM-вызовы — 4 формата с одним провайдером; ask_json с loose-парсером проще и без зависимостей; instructor добавляет value при десятках схем/моделей |
| **phonenumbers** (libphonenumber) | нам нужен не парсинг произвольных номеров, а матчинг «+7-маски» в русском тексте; наш regex уже даёт валидные +7 (XXX) форматы. В prod — да, для валидации |
| **tenacity / backoff** (retry-обёртки) | retry-циклы по 5 строк уже написаны в llm/gosplan/xmlstock; библиотека окупается при десятках внешних вызовов |
| **HTMX / Alpine.js / React** | UI — одна страница с SSE-таблицей; ванильный JS ~300 строк без сборщика. Фреймворк не добавит ценности, но добавит импорты |
| **gspread** (Google Sheets API) | требует сервис-аккаунт Google; для прототипа CSV-экспорт «открывается в Sheets» — то же UX без secrets |
| **zakupki.gov.ru парсеры с GitHub** | официальный API Госплана чище парсинга ЕИС: без капчи/лимитов/прокси, уже даёт ИНН+цены исполненных контрактов |

## Где готового нет (собственный код)

- **optlist.ru** — каталог за Anubis PoW: Playwright-клиент + парсер микроформата schema.org (уникальная задача);
- **merge-слой** (дедуп по домену/ИНН + fuzzy-имена + provenance) — предметная логика сервиса;
- **SSE-пайплайн** с этапами — специфика продукта, FastAPI даёт только транспорт;
- **RFQ-рассылка** — smtplib + LLM-генерация текста; готового нет.

## Вывод

Ядро данных (SERP, госконтракты, каталог) — тонкие клиенты над внешними API +
две библиотеки качества (trafilatura, price-parser) и одна для матчинга
(rapidfuzz). Краулерного/LLM-фреймворка не тянем — прототип обязан
запускаться одной командой и не иметь лишних зависимостей, а масштабный
вариант (crawl4ai, instructor, phonenumbers, tenacity, Postgres) — задокументирован
как путь развития.
